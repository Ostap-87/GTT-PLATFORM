# GTT-PLATFORM: правила работы с репозиторием

White label платформа для организаторов деловых поездок: приложение участника под брендом организатора, вход по коду
приглашения и конструктор организатора (логотип, название, цвет, блоки экрана). Основа — приложение GTT из
`Ostap-87/GTT-APP`. Пиши пользователю по-русски.

## Связь с GTT-APP (решение пользователя 21.10.2026: «чтобы они не смешивались»)

- **GTT-APP** — готовое приложение Global Tech Tour, без white label. **Здесь** — всё white label: организаторы
  (`mobile/src/data/tenant.ts`), коды приглашения (`/join`), конструктор (`/builder`), разбор рынков (`docs/market-research.md`).
- Улучшения общего приложения (экраны делегата, координатора, агента, дизайн) делаются в GTT-APP, сюда их забирает слияние:
  `git fetch https://github.com/Ostap-87/GTT-APP.git main && git merge FETCH_HEAD`. При конфликте в файлах white label
  оставляй версию платформы. Обратно в GTT-APP конструктор и white label не переносим.
- Коммит GTT-APP «Разделение…» (ac3722d), который убрал там white label, здесь уже учтён без применения (`merge -s ours`),
  поэтому слияния из GTT-APP конструктор не удаляют.
- Свой проект Expo `@ostap87s-team/gttplatform` (https://expo.dev/accounts/ostap87s-team/projects/gttplatform, создан
  21.10.2026): `mobile/app.json` — «GTT Platform», slug `gttplatform`, свой `projectId`; QR-код — в сводке прогона
  «Приложение — Expo Go». Секрет `EXPO_TOKEN` — в настройках **этого** репозитория. При слиянии из GTT-APP `mobile/app.json`
  всегда остаётся платформенным (название, slug, `projectId`, адрес обновлений).
- Документы и дизайн приложения GTT (`docs/architecture.md`, `design/`) ведутся в GTT-APP; здесь — их копии из слияний.
  Решения по white label записывай в `docs/decisions.md` этого репозитория.

## Кабинет организатора (решение пользователя 21.10.2026)

«Загружать информацию через Excel, PDF, Word и вручную… обязательно десктопная версия и через браузер, чтобы работать
с любого устройства, в том числе с планшета». Путь клиента — [`docs/client-journey.md`](docs/client-journey.md).

- `/org` — кабинет: компания → бренд → программы → поездка → участники → приглашение (`src/app/org.tsx`, шаги —
  `src/ui/org-steps.tsx`, форма бренда — `src/ui/brand-form.tsx`, предпросмотр телефона — `src/ui/org-ui.tsx`). Раскладка
  под ширину: от 1100 px — меню слева, форма, телефон справа; от 860 — шаги сверху, телефон справа; уже — предпросмотр
  по кнопке. `/org?id=<организатор>&step=<шаг>` открывает нужный шаг. Все шаги открыты сразу: без названия кабинет
  создаётся сам («Новый организатор»), `/org?new=1&step=programs` — сразу к загрузке программы.
- Данные организатора — `src/data/org.ts`: программы, поездки, участники, ключ `org.<id>` на устройстве (до сервера).
  **Пустой старт:** у нового организатора нет программ и поездок GTT; в приложении участника — его опубликованная
  поездка (`applyOrg` в `src/data/active.ts`), пока её нет — вымышленный пример, но не программы GTT.
- Загрузка файлов — `src/data/import.ts`, всё на устройстве: `.xlsx` и `.docx` (zip, `fflate`), `.csv`, PDF — pdf.js из
  `mobile/public/pdfjs/` (только в браузере; путь сайта — `webBase()`). Распознанное всегда открывается в редакторе на
  проверку. Старые `.xls`/`.doc` — просим пересохранить. Новые синонимы столбцов — в `HEAD`/`PHEAD`.
- QR-код — настоящий (`src/data/qr.ts`, `qrcode-generator`). Ссылка-приглашение в браузере — с адреса сайта, в приложении —
  `WEB_URL` (GitHub Pages).
- Веб-версия — GitHub Pages (`.github/workflows/pages.yml`): https://ostap-87.github.io/GTT-PLATFORM/ (кабинет — `/org`).
  Сборка с `experiments.baseUrl: /GTT-PLATFORM` только в CI, локально — без него.
- Проверка в браузере (Playwright): имена загружаемых файлов — латиницей (с кириллицей тестовый Chromium отменяет выбор
  файла; у людей в обычном браузере всё работает).

## Языки, тема и лендинг (решение пользователя 21.10.2026)

- Шесть языков: русский, английский, китайский, казахский, арабский (справа налево), хинди. Выбор — при первом запуске
  и в «Язык и тема» (`/settings`). Любая новая надпись — `__('Русская фраза')` из `@/i18n` и перевод во все пять словарей
  `mobile/src/i18n/*.json`; проверка — `node tools/i18n-keys.mjs` (у всех языков «нет 0»). Подробности — `mobile/README.md`.
- Тема светлая и тёмная (и «как в системе») — в приложении и кабинете; цвета только из `C`/`SH` (`src/ui/theme.ts`),
  никаких `'#fff'` для фона карточек и плашек — иначе тёмная тема ломается.
- Лендинг (макет для продаж) — `mobile/public/landing/index.html`, https://ostap-87.github.io/GTT-PLATFORM/landing/.
  Название платформы, тарифы, цены и контакты — заглушки `[уточнить …]`, пока их не дал пользователь.
- Проверка в браузере: главную GTT («/», 3D-заставка) Playwright не снимает — заходить через `/org` или `/demo`; язык
  задавать заранее (`localStorage gtt:pref:lang`), иначе откроется экран выбора языка.

## Что где хранить (решение пользователя 15.10.2026)

Всё по проекту приложения — документы, инструкции, дизайн, потом код — хранится **в этом репозитории**:

- `docs/architecture.md` — архитектура. Рабочая версия с комментариями — Claude Docs
  (https://claude.ai/artifact/6nudCcLPP5eTTKeu6WhLGp, проект `2ee697fe-9e34-496c-84cb-96dd183149f1`).
  Правишь документ — в том же заходе обнови и `docs/architecture.md`.
- `docs/decisions.md` — журнал: что решил пользователь, что ещё предложение. Каждую новую договорённость
  записывай сюда с датой.
- `docs/*.md` — остальные проработки (например, `wechat-mini-program.md`).
- `docs/market-research.md` — рынки технологического туризма и MICE, конкуренты, модель white label (21.10.2026). Рабочая
  версия с диаграммами — Claude Docs https://claude.ai/artifact/Cg9az4DRCa6CMrLtmvjciE; правишь её — обнови и файл.
- `design/canvas/` — копия файлов холста Claude Design (https://claude.ai/artifact/8Tw2bADzTCNwschFSXRMAy,
  файлы `project/*.dc.html` и `canvas.json`). После правок на холсте скопируй изменённые файлы сюда и пересобери
  превью: `node tools/render-previews.mjs`, затем `python3 tools/role-sheets.py`.
- `design/prototype/index.html` — кликабельный прототип (артефакт https://claude.ai/artifact/WqVbtPczcM5Vny7N5f1Jym):
  одна страница без зависимостей, общее состояние четырёх ролей. Правишь — публикуй тот же файл в тот же артефакт и коммить.
- `design/previews/` — PNG экранов и листы-обзоры по ролям (`_делегат.jpg`, `_координатор.jpg`, `_компания.jpg`):
  их и показывай пользователю в чате после каждой правки.

## Приложение (Expo) — `mobile/`

- React Native + Expo SDK 57, Expo Router (`mobile/src/app/`); описание и команды — `mobile/README.md`.
- Версия SDK — та, что открывает Expo Go из App Store (16.10.2026 там 57.0.9, SDK 58 он не открывает).
  Проверка: `curl -s 'https://itunes.apple.com/lookup?id=982107779&country=ru'`. Переход на новый SDK —
  только когда Expo Go с ним вышел в App Store: `npx expo install expo@~<SDK>.0.0 && npx expo install --fix`.
- Пакеты — только `npx expo install`; перед API Expo читать документацию своей версии (`docs.expo.dev/llms.txt`), не память.
- Перед пушем: `npm run typecheck` и `npm run export:web` в `mobile/` — без ошибок; снимки экранов для чата — Playwright
  по веб-сборке (`dist/`), лист — `design/previews/_приложение-<тема>.jpg`.
- Дизайн — «пластилин» (решение 21.10.2026): цвета и тени только из `src/ui/theme.ts` (`C`, `SH`), элементы — из `src/ui/kit.tsx`,
  движение — `src/ui/motion.tsx` (с учётом «Уменьшить движение»), нижняя панель — `src/ui/TabBar3D.tsx`; подробности — `mobile/README.md`.
- White label (решение 21.10.2026): организатор — `src/data/tenant.ts` (`TENANT`, `applyTenant`). Цвета бренда (`C.blue*`, `C.hero*`,
  `SH.blue`, `SH.hero`) — только при рендере, не в `StyleSheet.create`; название и координатор — из `TENANT`, а не «GTT» в коде.
  Быстрый конструктор бренда с телефона — `/builder`, полный кабинет — `/org` (выше); пока сервера нет, свои организаторы
  хранятся на устройстве (`tenants.custom`). Новый блок «Сегодня» — ключ в `TODAY_BLOCKS` и ветка в `block()`.
- Всё, что зависит от страны поездки (валюта, язык, подготовка, приложения, карта регионов), — профиль в `src/data/countries.ts`
  (9 стран, решение 21.10.2026); новый экран берёт страну из `TRIP.country`, а не пишет «Китай» в коде.
- Каталог — `node tools/sync-catalog.mjs` из клона SINOTECH (цен в каталоге нет); тестовая поездка — `src/data/trip*.ts`,
  только вымышленные делегаты. Любая из программ сайта открывается глазами делегата (`/demo`: страна → программа,
  `src/data/demo-trip.ts`, решение 21.10.2026): данные поездки меняются на месте через `src/data/active.ts`, поэтому массивы
  и словари поездки не пересоздавать, а производные считать функциями или в `refresh…()`.
- Модули, которых нет в Expo Go (например, expo-calendar), — только с запасным путём (файл `.ics` и т. п.) и проверкой
  `Constants.executionEnvironment`; документы, расходы и визитки делегата хранятся только на телефоне и в репозиторий не попадают.
- На телефон — GitHub Actions «Приложение — Expo Go» (секрет `EXPO_TOKEN`), QR-код в сводке прогона.
- Места на диске мало: после установки пакетов `npm cache clean --force`.

## Мини-программа WeChat и сервер

- `miniprogram/` — нативный WXML/WXSS/JS без сборщика (решение 15.10.2026: что в репозитории, то и в WeChat).
  Тексты — только через `utils/i18n.js` (китайский и английский), стиль — `app.wxss`.
- `server/` — Node.js без внешних зависимостей; секреты только из переменных окружения (`server/README.md`).
- Перед каждым пушем кода: `npm test --prefix server` и `node tools/mp-check.mjs` — всё зелёное.
  Новая функция мини-программы = новый сценарий в `tools/mp-check.mjs` и тест сервера.
- Картинки экранов мини-программы для показа в чате — `node tools/mp-shots.mjs` (лист `design/previews/_мини-программа.jpg`).
- Загрузка в WeChat — `tools/mp-ci.mjs` или GitHub Actions «Мини-программа WeChat» (preview → QR в артефактах).
  Модерацию и публикацию нажимает пользователь в кабинете mp.weixin.qq.com.
- Номера паспортов и телефоны делегатов на сервер мини-программы не передаём (сервер это проверяет).

## Роли и правило доступа

Пять ролей: делегат, координатор, принимающая сторона, агент (турагентства и агенты-партнёры, решение 16.10.2026) и администратор
(«Центр поездки» на телефоне и компьютере, доступ полный или ограниченный — решение 21.10.2026; что входит в уровни, решим отдельно).
Координатор видит и меняет всё и может смотреть глазами делегата, компании или агента. Принимающая сторона видит
только свой визит и не видит телефонов делегатов; контакты передаются только с согласия делегата. Агент видит
каталог программ, выезды и свободные места и только свои заявки; делегатов, поездку изнутри и других агентов не видит. Подробности — «Кто что видит» в `docs/architecture.md`.
Профиль делегата (питание, аллергии, номер, здоровье, языки, интересы — решение 16.10.2026) целиком видит только
координатор; серьёзные аллергии — ещё гид и переводчик; компании — имя, должность и компанию; ресторан — сводку питания
и аллергий без имён. Аллергии и здоровье — особая категория данных: только с отдельным согласием, удаляются через 30 дней
после поездки, если участник не поставил «Сохранить профиль для следующих поездок». Анкета при первом заполнении —
4 шага по очереди (решения 16.10.2026, `docs/profile-cjm.md`).

## Содержание

- Факты о программах и компаниях — только с сайта globaltechtour.ru (данные — `Ostap-87/SINOTECH`,
  `src/data/tours.json`, `companies.json`) или от пользователя; нет данных — явная заглушка `[уточнить …]`.
- Цены программ в приложении не показываем (решение пользователя по презентациям: «так будет честнее»).
  Для агентов подготовлены поля «Стоимость для агента» и «Комиссия агента» (решение 16.10.2026) — пока пустые,
  заполняем только по решению пользователя.
- В макетах и тестовых данных — только вымышленные делегаты. Настоящие персональные данные в репозиторий не кладём
  (152-ФЗ: данные граждан России — только на сервере в России).
- Стиль — как у сайта и презентаций GTT: синий `#1a73e8`, Inter, Sofia Sans Extra Condensed, Noto Sans SC.

## Секреты

Репозиторий **публичный**. Ключи Apple и Google, токены Expo, AppSecret и ключ загрузки WeChat, ключи WeChat Pay,
ключ вебхука WeCom, пароли сервера — только в секретах GitHub и переменных сервера.
Никогда не проси прислать их в чат и не коммить. AppID мини-программы не секретный.

## Куда отправлять

Коммить и пушь в `main`, после каждой сохранённой правки документов или дизайна. Правила (этот файл,
`README.md`) обновляй в том же коммите, где появилась новая договорённость или возможность.
